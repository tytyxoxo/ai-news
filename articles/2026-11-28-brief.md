## 1. ชิปโฟโตนิกส์ใช้คลื่นแสงรันโมเดล AI หวังลดพลังงานดาต้าเซ็นเตอร์

Wired รายงานว่าต้นทุนพลังงานในการรัน AI กำลังพุ่งสูงขึ้นตามความซับซ้อนของโมเดล แล็บ AI และผู้ให้บริการคลาวด์จึงพยายามสร้างดาต้าเซ็นเตอร์ในพื้นที่ที่มีพลังงานหมุนเวียนราคาถูกอย่างสแกนดิเนเวีย แต่ติดปัญหาทั้งด้านโลจิสติกส์ ชิ้นส่วนขาดแคลน และกระแสต่อต้านดาต้าเซ็นเตอร์ สตาร์ทอัพฮาร์ดแวร์กลุ่มหนึ่ง เช่น Q.ANT จากเยอรมนี จึงหันไปพัฒนา photonic processor ที่ประมวลผลด้วยคลื่นแสงแทนการเคลื่อนที่ของอิเล็กตรอนแบบ GPU

แนวคิดนี้น่าสนใจเพราะแสงไม่สร้างความร้อนระหว่างเดินทางและประมวลผลข้อมูลพร้อมกันได้มากขึ้น จึงช่วยลดภาระระบบระบายความร้อนซึ่งเป็นต้นทุนก้อนใหญ่ของดาต้าเซ็นเตอร์ แต่ตัวเลขประหยัดพลังงานยังเป็นคำกล่าวอ้างที่ต้องรอพิสูจน์ในงานจริง เป้าหมายคือให้ทำงานคู่กับ GPU ไม่ใช่แทนที่ ฝั่ง developer จึงต้องดูว่าจะมี software stack ที่แบ่งงานระหว่างสองชิปได้ราบรื่นหรือไม่ ส่วนธุรกิจจะได้ทางเลือกลดค่าไฟโดยไม่ต้องย้ายดาต้าเซ็นเตอร์

**จับตา:** ผลทดสอบประสิทธิภาพต่อวัตต์ของชิปโฟโตนิกส์เมื่อรันงาน AI จริงเทียบกับ GPU และการรองรับจากเฟรมเวิร์กยอดนิยม

ที่มา: [Wired](https://www.wired.com/story/a-new-breed-of-chip-runs-ai-models-using-waves-of-light/)

## 2. Hugging Face ทดลองสร้างวิดีโอด้วย LTX-2.5 บน AWS Trainium3

Hugging Face เล่าประสบการณ์ที่ได้ใช้เครื่อง AWS Trainium3 (trn3.48xlarge, 64 NeuronCores) เป็นเวลาหนึ่งเดือนผ่านความร่วมมือกับ AWS โดยส่วนใหญ่ใช้ทดสอบและทำให้โมเดลบน Hugging Face รันได้มากขึ้น ช่วงท้ายทีมทดลองสร้างวิดีโอด้วย LTX-2.5 ของ Lightricks ซึ่งสร้างภาพและเสียงพร้อมกันผ่าน diffusers เมื่อโหลดโมเดลแล้ว คลิปยาว 10 วินาทีพร้อมเสียงใช้เวลาสร้างราว 22–23 วินาทีบนครึ่งเครื่อง

นี่เป็นสัญญาณว่าชิป AI ที่ไม่ใช่ Nvidia เริ่มรันงาน generative video ที่หนักได้จริงผ่านไลบรารีที่ developer คุ้นเคย อย่างไรก็ตามผู้เขียนยอมรับว่าหาตัวเลขเทียบกับ CUDA ที่น่าเชื่อถือไม่ได้ มีเพียงคำกล่าวอ้างของ LTX ว่าใช้ 6.8 วินาทีบน B200 สี่ตัวโดยไม่ระบุวิธีวัด จึงยังสรุปว่าเร็วกว่าหรือช้ากว่าไม่ได้ สำหรับธุรกิจที่ทำคอนเทนต์วิดีโอ นี่คือทางเลือกด้านฮาร์ดแวร์ที่อาจช่วยลดการพึ่งพา GPU ซึ่งขาดตลาด

**จับตา:** ลองดูว่าโมเดลใน diffusers ที่ทีมใช้อยู่รันบน Trainium ได้กี่ตัว และมี benchmark มาตรฐานเทียบกับ GPU ออกมาเมื่อไร

ที่มา: [Hugging Face](https://huggingface.co/blog/video-trainium3)

## 3. Satya Nadella ยอมรับไมโครซอฟท์มองพลาด ไม่คิดว่า Claude Code จะทำให้ IDE หมดความสำคัญ

Blognone รายงานว่า Satya Nadella ซีอีโอไมโครซอฟท์ ให้สัมภาษณ์รายการ The Pragmatic Engineer ของ Gergely Orosz และยอมรับว่าบริษัทมองข้ามการมาของเครื่องมือ AI เขียนโค้ดอย่าง Cursor และ Claude Code ที่ทำให้ IDE ซึ่งไมโครซอฟท์ครองตลาดมานานลดความสำคัญลงในเวลาเพียงครึ่งปี แม้บริษัทจะปรับตัวด้วย VS Code และ GitHub Copilot มาตลอด แต่ไม่ได้คาดว่า AI ที่เขียนโค้ดเองได้ทั้งหมดจะเข้ามาแทนที่เร็วขนาดนี้

Nadella มองว่า IDE จะไม่หายไป แต่จะเกิดใหม่ในรูปแบบที่เน้นการป้อนสเปกและจัดการไฟล์ markdown แทนการพิมพ์โค้ดเอง ประเด็นสำคัญที่เขาชี้คือการสร้างโค้ดถูกลงมาก แต่การตรวจสอบยืนยันโค้ดยังยาก และการใช้โมเดลอีกตัวมาตรวจก็เกิดคำถามซ้อนว่าตัวตรวจเชื่อถือได้แค่ไหน สำหรับ developer นี่หมายถึงทักษะการเขียนสเปก การรีวิว และการทดสอบจะมีค่ามากขึ้น ส่วนองค์กรต้องลงทุนกับกระบวนการ verification มากกว่าการเร่งผลิตโค้ด

**จับตา:** ไมโครซอฟท์จะปรับ VS Code และ GitHub Copilot ไปสู่ workflow แบบ spec-driven อย่างไร และมีเครื่องมือ verification ใหม่ออกมาหรือไม่

ที่มา: [Blognone](https://www.blognone.com/node/152267)

## 4. MiniMax ยอมรับระบบตรวจความปลอดภัยอ่านพรอมต์ แม้ผู้ใช้ซื้อ API ผ่านผู้ให้บริการรายอื่น

Blognone รายงานต่อเนื่องจากกรณีผู้ให้บริการ LLM บน OpenRouter ถูกแฮก โดยนักวิจัยพบว่าพรอมต์ที่ส่งไปยังโมเดล MiniMax ผ่านผู้ให้บริการหลายรายถูกอ่าน MiniMax ออกมายอมรับว่าเป็นระบบตรวจสอบความปลอดภัยของบริษัทเอง ไม่ว่าจะซื้อ API กับ MiniMax โดยตรงหรือผ่านรายอื่นอย่าง Novita พรอมต์ก็อาจถูกส่งกลับไปยัง MiniMax ระบบจะดึงไอพีและ URL ในพรอมต์ไปตรวจ จึงเปิด URL ลับที่นักวิจัยใส่ไว้

กรณีนี้เตือนว่าการเรียกโมเดลผ่านตัวกลางไม่ได้หมายความว่าข้อมูลจะอยู่แค่กับตัวกลาง เจ้าของโมเดลอาจยังเห็นข้อมูลอยู่ developer ที่ส่ง URL ภายใน token หรือข้อมูลลูกค้าในพรอมต์จึงต้องประเมิน data flow ใหม่ ไม่ใช่ดูแค่สัญญากับผู้ให้บริการที่จ่ายเงิน แม้ MiniMax จะปรับนโยบายให้ไม่เปิด URL อีกสำหรับการใช้งานแบบธุรกิจ แต่การตรวจพรอมต์ยังเกิดขึ้นอยู่ ซึ่งองค์กรที่มีข้อกำหนดด้านความเป็นส่วนตัวควรนำไปพิจารณา

**จับตา:** ตรวจสอบเงื่อนไขการใช้ข้อมูลของทั้งผู้ให้บริการตัวกลางและเจ้าของโมเดลก่อนส่งข้อมูลอ่อนไหวผ่าน API ของโมเดลจีนหรือ aggregator

ที่มา: [Blognone](https://www.blognone.com/node/152265)

## 5. SAP เตรียมลดพนักงานอย่างน้อย 10,000 ตำแหน่ง เพื่อปรับธุรกิจสู่ยุค AI

Bloomberg รายงานโดยอ้างแหล่งข่าวที่ทราบเรื่องว่า SAP SE กำลังเตรียมแผนลดตำแหน่งงานอย่างน้อย 10,000 ตำแหน่ง เพื่อปรับโครงสร้างธุรกิจซอฟต์แวร์ให้รับกับยุค AI ต่อจากที่ Oracle และ Microsoft ลดคนไปก่อนหน้านี้

ข่าวนี้ยังเป็นข้อมูลจากแหล่งข่าวและยังไม่มีรายละเอียดว่าตำแหน่งใดจะได้รับผลกระทบ แต่ตอกย้ำแนวโน้มที่บริษัทซอฟต์แวร์องค์กรรายใหญ่ใช้ AI เป็นเหตุผลในการปรับโครงสร้างคน สำหรับลูกค้า ERP ที่พึ่งพา SAP ควรจับตาว่าการปรับครั้งนี้จะกระทบงานซัพพอร์ตและที่ปรึกษาหรือไม่ ส่วนคนทำงานสายซอฟต์แวร์องค์กรอาจต้องเร่งปรับทักษะให้สอดคล้องกับทิศทางใหม่

**จับตา:** การประกาศอย่างเป็นทางการของ SAP ว่าจะลดคนในส่วนใด และจะลงทุนกับผลิตภัณฑ์ AI ด้านไหนแทน

ที่มา: [Bloomberg](https://www.bloomberg.com/news/articles/2026-11-26/sap-weighs-cutting-at-least-10-000-positions-in-ai-restructuring)
