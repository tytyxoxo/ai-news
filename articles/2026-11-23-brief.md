## 1. หัวหน้านักวิทยาศาสตร์ OpenAI เสนอใช้ perplexity เป็นมาตรวัดกลางของความก้าวหน้า AI พร้อมเปิดตัวเลขภายในของบริษัท

Jakub Pachocki หัวหน้านักวิทยาศาสตร์ของ OpenAI เผยแพร่บทความ "Perplexity and Intelligence" โต้แย้งว่าความสามารถของ AI ยุคใหม่ส่วนใหญ่มาจากกระบวนการเดียวที่เรียบง่ายแต่ตีความยาก คือการฝึกตัวบีบอัดหรือตัวทำนายบนคลังข้อมูลขนาดมหาศาล เขาจึงเสนอให้ใช้ perplexity หรือ cross-entropy loss เป็นมาตรวัดเปรียบเทียบระหว่างผู้พัฒนาโมเดล และเป็นฐานของมาตรฐานความปลอดภัยร่วมกัน โดย OpenAI เริ่มเปิดเผยค่า perplexity ภายในจากการ pretrain ของตัวเองเป็นก้าวแรก แม้ยอมรับว่าทำให้คู่แข่งเห็นสถานะของบริษัทชัดขึ้น

ข้อเสนอนี้ออกมาในช่วงที่วงการถกเถียงเรื่องการชะลอการพัฒนา AI และคำถามสำคัญคือจะวัด "ความเร็ว" อย่างไร benchmark ที่วัดความสามารถปลายทางล้าสมัยเร็วมาก ขณะที่ perplexity วัดได้ต่อเนื่องตั้งแต่ระหว่างฝึก แต่ข้อจำกัดคือค่านี้ขึ้นกับชุดข้อมูลทดสอบและ tokenizer การเทียบข้ามบริษัทจึงต้องตกลงเงื่อนไขร่วมกันก่อน และ perplexity ที่ต่ำลงก็ไม่ได้บอกตรงๆ ว่าโมเดลอันตรายขึ้นแค่ไหน สำหรับธุรกิจ นี่อาจเป็นจุดเริ่มของกรอบกำกับดูแลที่อิงตัวเลขจากการฝึกโมเดล

**จับตา:** Anthropic, Google DeepMind และค่ายอื่นจะยอมเปิดเผยค่า perplexity บนชุดข้อมูลกลางตามที่ OpenAI เสนอหรือไม่

ที่มา: [OpenAI](https://openai.com/index/perplexity-and-intelligence)

## 2. ผู้ให้บริการ LLM บน OpenRouter 3 รายถูกแฮก พรอมต์ลูกค้าหลุด แม้บางรายประกาศว่าไม่เก็บข้อมูล

Blognone รายงานว่าผู้ให้บริการ LLM สามรายที่ให้บริการผ่าน OpenRouter ได้แก่ Novita, Phala และ Together ถูกแฮกและคนร้ายดึงพรอมต์ของลูกค้าออกไปได้ ความเสียหายกว้างเพราะพรอมต์อาจมี API key หรือรหัสผ่านระบบอื่นอยู่ด้วย ที่น่ากังวลคือบางรายประกาศเป็น Zero Data Retention (ZDR) แต่จริงๆ ยังเก็บพรอมต์ไว้ Dragos ทดลองปล่อย AWS key ในบทสนทนากับ LLM แล้วพบคนร้ายพยายามใช้กุญแจภายในวันเดียว OpenRouter ยืนยันว่าไม่ใช่ช่องโหว่ของตัวเอง และถอดป้าย ZDR จากผู้ให้บริการอื่นอีก 125 รายการ

เหตุการณ์นี้ยืนยันความเสี่ยงที่นักวิจัยเตือนไว้ว่าห่วงโซ่ AI router รั่วข้อมูลได้ง่าย ป้าย ZDR ที่ developer ใช้ตัดสินใจเลือกผู้ให้บริการกลับเชื่อถือไม่ได้ถ้าไม่มีการตรวจสอบ ทีมที่ส่งพรอมต์ผ่าน router ควรถือว่าทุกอย่างในพรอมต์อาจหลุด ต้องกรอง secret ออกก่อนส่ง และหมุนเวียนกุญแจที่อาจเคยหลุดเข้าไปทันที สำหรับองค์กร การเลือกผู้ให้บริการราคาถูกที่สุดผ่าน router อาจแลกมากับความเสี่ยงด้านข้อมูลที่มองไม่เห็น

**จับตา:** ผลการตรวจสอบผู้ให้บริการที่ OpenRouter ประกาศว่าจะทำ และว่าจะมีมาตรฐานรับรอง ZDR จากภายนอกหรือไม่

## 3. Wells Fargo ปรับข้อตกลงลูกค้า ใช้ AI agent กับบัญชีธนาคาร "ความเสี่ยงเป็นของคุณเอง"

Wired รายงานว่า Wells Fargo จะเริ่มใช้ข้อตกลงฉบับปรับปรุงกับลูกค้าหลายล้านรายตั้งแต่วันอังคาร โดยมีเนื้อหาเฉพาะเรื่อง AI agent และระบุชัดว่า "การใช้ AI Agent ใดๆ เป็นความเสี่ยงของคุณเอง" AI agent ที่ทำงานออนไลน์และคลิกแทนผู้ใช้ยังเป็นเทคโนโลยีที่ล้มลุกคลุกคลานตลอดปี 2026 มีผู้ใช้กลุ่มหนึ่งที่ได้ประโยชน์จากระบบอัตโนมัติ แต่ก็มีกรณีที่ agent ทำพลาดครั้งใหญ่ เช่น โพสต์รายละเอียดบัญชีธนาคารให้คนที่ทำงานเห็น ขณะที่ผู้ใช้จำนวนมากยอมผูกรหัสผ่านและให้สิทธิ์กับ agent โดยไม่สนใจความปลอดภัย

ท่าทีของธนาคารสะท้อนช่องว่างระหว่างการตลาดของ agent ที่ขายภาพผู้ช่วยช้อปปิ้งและจัดการธุระทุกอย่าง กับระบบการเงินที่ออกแบบมาโดยถือว่าคนที่ล็อกอินคือเจ้าของบัญชีตัวจริง เมื่อความรับผิดถูกผลักกลับไปที่ผู้ใช้ ความเสียหายจาก agent ทำพลาดอาจไม่ได้รับการชดเชย ฝั่ง developer ที่สร้าง agent ควรหันไปใช้การเชื่อมต่อแบบมอบสิทธิ์จำกัด เช่น OAuth ที่กำหนดขอบเขตได้ แทนการเก็บรหัสผ่านของผู้ใช้ และผู้ใช้ควรอ่านเงื่อนไขธนาคารก่อนให้ agent แตะบัญชี

**จับตา:** ธนาคารอื่นจะออกเงื่อนไขแบบเดียวกันหรือไม่ และจะมีช่องทางเชื่อมต่อสำหรับ agent อย่างเป็นทางการเกิดขึ้นหรือเปล่า

ที่มา: [Wired](https://www.wired.com/story/banks-are-cracking-down-on-ai-agents/)

## 4. ที่ประชุม UN ที่เจนีวาตกลงกฎคุม "หุ่นยนต์สังหาร" ไม่ได้ ได้แค่รับปากจะ "เริ่มหารือทางเลือก"

The Verge รายงานว่าการประชุมของนักการทูต UN ที่เจนีวาสัปดาห์นี้ซึ่งมีวาระวางกฎเกณฑ์การใช้อาวุธอัตโนมัติ หรือที่เรียกกันว่า "หุ่นยนต์สังหาร" จบลงโดยแทบไม่มีความคืบหน้า ผู้แทนตกลงกันได้เพียงว่าจะ "เริ่มหารือทางเลือก" ทั้งที่ก่อนการเจรจา คณะกรรมการกาชาดระหว่างประเทศ ผู้พิทักษ์อนุสัญญาเจนีวา ระบุว่าเร่งด่วนที่ต้องร่างกฎที่มีผลผูกพันทางกฎหมายภายในหนึ่งปี ซึ่งได้รับการสนับสนุนจากเลขาธิการ UN และสมเด็จพระสันตะปาปาลีโอ

ความล้มเหลวนี้แปลว่าการพัฒนาอาวุธที่ใช้ AI เลือกและโจมตีเป้าหมายจะเดินหน้าต่อโดยไม่มีกรอบระหว่างประเทศรองรับ ประเด็นยากคือการนิยามว่าระดับความเป็นอัตโนมัติเท่าใดจึงต้องควบคุม และใครรับผิดเมื่อระบบตัดสินใจผิด ฝั่งบริษัทเทคและนักวิจัยที่ทำ computer vision หรือระบบอัตโนมัติก็ยังต้องเผชิญคำถามเรื่องการนำงานไปใช้ทางทหารต่อไป โดยไม่มีเส้นแบ่งชัดเจนที่ตกลงกันในระดับโลก

**จับตา:** ประเทศกลุ่มที่ต้องการกฎผูกพันจะแยกไปเจรจาสนธิสัญญานอกกรอบ UN หรือไม่ หากการหารือรอบหน้ายังไม่คืบ

ที่มา: [The Verge](https://www.theverge.com/tech/1039554/un-regulations-killer-robots)

## 5. Binding of Isaac ถอดเพลง AI ออกจาก Repentance Plus หลังถูกรีวิวถล่มบน Steam

เกม The Binding of Isaac: Repentance Plus ถูกผู้เล่นรีวิวถล่มบน Steam หลายวัน หลังผู้ใช้ Reddit ชื่อ ShweetsStuff พบว่าเพลงในช่วงที่ล้อเลียนเกม Grand Theft Auto ใช้เพลงที่สร้างด้วย AI โดยเจอไฟล์เสียงที่มี metadata ของ Suno ชี้กลับไปยังเพลงบนเว็บ Suno Edmund McMillen ผู้สร้างเกมออกมาขอโทษบน X และบอกว่า "ไม่รู้เลย" ว่าส่วนนี้ใช้เพลง AI ซึ่ง Valve กำหนดให้นักพัฒนาต้องเปิดเผยว่าใช้ generative AI ในการพัฒนาเมื่อใดและอย่างไร ผู้พัฒนาจึงถอดเพลงเหล่านั้นออก

กรณีนี้ชี้ว่าการใช้ generative AI ในงานสร้างสรรค์ไม่ได้จบที่ตัวผู้สร้าง แต่ไหลผ่านผู้รับจ้างและซัพพลายเออร์ที่เจ้าของงานอาจไม่รู้ และ metadata ที่ติดมากับไฟล์ก็ทำให้ชุมชนตรวจพบได้ง่าย สำหรับสตูดิโอเกมหรือทีมคอนเทนต์ บทเรียนคือต้องมีกระบวนการตรวจที่มาของ asset ทุกชิ้นก่อนปล่อย เพราะกฎเปิดเผยของแพลตฟอร์มทำให้ความผิดพลาดกลายเป็นปัญหาความน่าเชื่อถือ และผู้เล่นกลุ่มหนึ่งพร้อมลงโทษด้วยรีวิวทันที

**จับตา:** Valve จะลงโทษผู้พัฒนาที่ไม่เปิดเผยการใช้ AI หรือไม่ และสตูดิโอจะเริ่มเขียนข้อห้ามใช้ AI ลงในสัญญากับผู้รับจ้างมากขึ้นแค่ไหน
