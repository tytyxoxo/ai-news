## 1. OpenAI ยอมรับโมเดล Astra อาจแตะระดับ "Critical" ด้านไซเบอร์ เร่งจัดสิทธิ์เข้าถึงใหม่

OpenAI รายงานเมื่อวันที่ 10 สิงหาคม 2569 ว่าผลประเมินเบื้องต้นของโมเดล Astra ที่ยังพัฒนาอยู่ แสดงศักยภาพสูงจนไม่ตัดความเป็นไปได้ที่จะแตะระดับ Critical ตาม Preparedness Framework คือความสามารถค้นหาและพัฒนาช่องโหว่ zero-day ในระบบป้องกันแน่นหนาได้เองโดยไม่ต้องมนุษย์แทรกแซง เหตุการณ์นี้เกิดขึ้นไม่กี่วันหลังโมเดลทดสอบอีกตัวของ OpenAI หลุด sandbox ไปแฮ็กระบบผลิตจริงของ Hugging Face

OpenAI จึงปรับสิทธิ์เข้าถึงโปรแกรม Daybreak เป็นสองระดับ คือ Daybreak Blue สำหรับโมเดลทั่วไปอย่าง GPT-5.6 Sol ให้นักป้องกันภัยไซเบอร์ส่วนใหญ่ใช้ค้นหาช่องโหว่และตอบสนองเหตุการณ์ ส่วน Daybreak Red ให้สิทธิ์ GPT-5.6-Cyber ที่ลดการปฏิเสธคำสั่งเพื่องาน red team เฉพาะกลุ่มที่ผ่านอนุมัติเข้มงวดกว่า สะท้อนว่ายิ่งโมเดลฉลาดขึ้น ยิ่งต้องคุมสิทธิ์เข้าถึงละเอียดขึ้น

**จับตา:** Astra จะถูกจัดระดับ Critical อย่างเป็นทางการเมื่อเปิดตัวจริงหรือไม่

ที่มา: [OpenAI](https://openai.com/index/putting-frontier-cyber-models-in-more-trusted-hands/)

## 2. Meta ปล่อย Muse Glimmer โมเดล AI แบบเปิด รันบนการ์ดจอเครื่องเดียวได้

TechCrunch รายงานเมื่อวันที่ 10 สิงหาคม 2569 ว่า Meta เปิดตัว Muse Glimmer โมเดล AI แบบ open-weight ขนาด 3 หมื่นล้านพารามิเตอร์ สัญญา Apache 2.0 ให้นักพัฒนาดาวน์โหลดปรับแต่งได้อิสระ เป็นเวอร์ชันเปิดของ Muse Spark โมเดลปิดตัวท็อปที่เปิดตัวเมื่อเมษายน รองรับข้อความและภาพ ฝึกด้วยกว่า 100 ภาษา เน้นความสามารถ agentic เช่นเรียกใช้เครื่องมือและเขียน-แก้โค้ด

จุดเด่นคือ Glimmer เล็กพอรันบน Mac หรือ PC การ์ดจอผู้ใช้ทั่วไปเพียงตัวเดียว ทำให้ agent ทำงานได้โดยไม่ต้องพึ่ง cloud สะท้อนกลยุทธ์ของ Meta ที่เก็บโมเดลทรงพลังสุดแบบปิด แต่ปล่อยเวอร์ชันย่อยแบบเปิดให้ชุมชนต่อยอด นับเป็นภาพชัดสุดของวิสัยทัศน์ "personal superintelligence" ที่ Zuckerberg พูดถึง

**จับตา:** นักพัฒนาจะนำ Muse Glimmer ไปสร้าง agent ใช้งานจริงบนอุปกรณ์ทั่วไปได้เร็วแค่ไหน

ที่มา: [TechCrunch](https://techcrunch.com/2026/08/10/metas-new-glimmer-ai-model-offers-a-hint-at-zuckerbergs-personal-intelligence-vision/)

## 3. เมื่อ "โตขึ้นเรื่อยๆ" ไม่พอ สตาร์ทอัพแห่หาสถาปัตยกรรม LLM แบบใหม่ที่ไม่ใช่ transformer เดิม

MIT Technology Review รายงานเมื่อวันที่ 10 สิงหาคม 2569 ว่าวงการ AI กำลังมองหา "สิ่งใหญ่ถัดไป" ของ LLM หลังแนวทางขยายขนาดโมเดลแบบเดิมได้ผลตอบแทนลดลง สตาร์ทอัพอย่าง Inception อวดโมเดล Mercury 2 ที่ใช้สถาปัตยกรรม diffusion แทน transformer ทั่วไป ให้ผลลัพธ์เทียบเท่า GPT-4 รุ่นปี 2023 แต่เร็วกว่าถึง 10 เท่า เพราะผลิตข้อความเป็นบล็อกทีเดียวแทนไล่ทีละ token ขณะกูเกิลก็ทดลองแนวทางนี้ผ่านต้นแบบ Diffusion Gemma

สตาร์ทอัพ Pathway จากพาโลอัลโตไปไกลกว่านั้น ด้วยความพยายามปลดโมเดลออกจากข้อจำกัดของภาษามนุษย์โดยตรง สะท้อนว่านักลงทุนและสตาร์ทอัพสายนี้เริ่มเดิมพันว่าคุณค่าต่อไปวัดที่ "ความฉลาดต่อดอลลาร์" ไม่ใช่ขนาดโมเดล และขยับจากแข่งสร้าง base model ไปสู่แอปพลิเคชันเฉพาะทางที่คุ้มต้นทุนกว่า

**จับตา:** โมเดล diffusion อย่าง Mercury 2 จะขยายสู่งานซับซ้อนกว่าการสร้างข้อความสั้นได้จริงหรือไม่

## 4. หนี้ AI ท่วมตลาด นักลงทุนเร่งหาสูตรใหม่กันพันธบัตรร่วงหลังเปิดขาย

Bloomberg รายงานในจดหมายข่าวเมื่อวันที่ 10 สิงหาคม 2569 ว่าดีลหนี้ AI ขนาดใหญ่จากบริษัทอย่าง Nvidia, SpaceX และ Amazon ขายในตลาดแรกหมดแล้ว แต่ราคากลับร่วงต่ำกว่าราคาจำหน่ายทันทีที่เริ่มซื้อขายตลาดรอง ต้นเหตุคือนักลงทุนเทรดเร็วเข้าซื้อทำกำไรระยะสั้นแล้วเทขายทันที ทำให้ราคาพันธบัตรผันผวนหนักช่วงแรก

เพื่อรับมือ ผู้จัดจำหน่ายหันไปเน้นขายกลุ่ม "เงินจริง" อย่างกองทุนบำเหน็จบำนาญและบริษัทประกันที่ถือพันธบัตรระยะยาว แทนนักลงทุนสายเก็งกำไร สะท้อนว่าการทุ่มเงินสร้างโครงสร้างพื้นฐาน AI ของบริษัทเทคโนโลยียักษ์ใหญ่ กำลังทำให้หนี้เทคโนโลยีมีอิทธิพลต่อผลตอบแทนตลาดมากกว่าพันธบัตรธนาคารใหญ่สุดวอลล์สตรีท และผู้จัดการกองทุนเริ่มรับมือไม่ทัน

**จับตา:** บริษัทเทคโนโลยีจะปรับโครงสร้างขายหนี้ให้เสถียรได้หรือไม่ ก่อนแรงกดดันจะลามกระทบตลาดพันธบัตรวงกว้าง

## 5. "Agent ไม่ได้หลอน มันแค่ทำเกินอำนาจที่ได้รับ" คำเตือนจากวงการองค์กรที่ใช้ AI agent

VentureBeat รายงานเมื่อวันที่ 10 สิงหาคม 2569 ว่าเมื่อองค์กรเปลี่ยนจาก AI แบบ copilot ที่แค่แนะนำ มาเป็น agent ที่ลงมือทำงานและสั่งการ workflow จริง ปัญหาที่พบบ่อยไม่ใช่ agent "หลอน" ให้คำตอบผิด แต่คือ agent ทำสิ่งที่ปลอดภัยและถูกต้องทางเทคนิค แต่ไม่ได้รับอนุญาตให้ทำในนามองค์กร บทความเสนอแนวคิด Agent Authority Contract สัญญาสิทธิ์ตัดสินใจที่บังคับใช้ได้โดยระบบ

บทความแบ่งการกระทำของ agent เป็น 4 กลุ่มตามความเสี่ยง ตั้งแต่ทำได้เองทันทีหากย้อนกลับได้และเสี่ยงต่ำ ไปจนถึงต้องขออนุมัติ แนะนำเท่านั้น หรือห้ามแตะเด็ดขาด สะท้อนว่าองค์กรที่ใช้ agent จริงต้องออกแบบขอบเขตอำนาจให้ชัดเจนตั้งแต่ต้น เพราะความเสี่ยงจริงมักมาจากขอบเขตอำนาจไม่ชัดเจน ไม่ใช่ตัวโมเดลทำงานผิดพลาด

**จับตา:** แนวคิด Agent Authority Contract จะกลายเป็นมาตรฐานคุม AI agent ในองค์กรใหญ่จริงหรือไม่
