## 1. OpenAI รวม Chat กับ Work ใน ChatGPT ใช้โควตาเดียวกัน ผู้ใช้หนักอาจชนลิมิตเร็วขึ้น

OpenAI เริ่มทยอยเปิดประสบการณ์ Chat และ Work แบบรวมเป็นหนึ่งเดียวใน ChatGPT ให้สมาชิก Pro กลุ่มเล็กๆ ก่อน ตามที่ Thibault Sottiaux หัวหน้าฝ่ายผลิตภัณฑ์โพสต์บน X หลังเคยแจ้งผู้ใช้ทางอีเมลไว้แล้ว ภายใต้ระบบใหม่ Chat และ Work จะใช้มาตรวัดการใช้งานร่วมกันเพียงตัวเดียว โฆษกของ OpenAI ยอมรับกับ TechCrunch ว่าผู้ใช้ส่วนใหญ่จะไม่ถูกรีเซ็ตโควตาถี่ขึ้น แต่ผู้ใช้กลุ่มที่ใช้หนักที่สุดส่วนน้อยอาจชนลิมิตเร็วกว่าเดิม ขณะที่การสนทนากับโมเดล Instant ยังไม่จำกัดและไม่นับรวมในโควตา

การเปลี่ยนแปลงนี้สะท้อนว่าต้นทุนการประมวลผลของโมเดล reasoning ยังเป็นข้อจำกัดจริงแม้กับบริษัทระดับ OpenAI การรวมโควตาทำให้บริหารทรัพยากรง่ายขึ้นฝั่งผู้ให้บริการ แต่ผู้ใช้บนฟอรัมกังวลว่าจะได้เข้าถึงโมเดลขั้นสูงน้อยลงทั้งที่จ่ายค่าสมาชิกเท่าเดิม สำหรับทีมหรือนักพัฒนาที่ใช้ ChatGPT เป็นเครื่องมือหลักในงานประจำวัน การวางแผนว่างานไหนควรใช้โมเดลหนัก งานไหนใช้ Instant ได้ จะกลายเป็นทักษะสำคัญ เพื่อไม่ให้โควตาหมดกลางงานที่เร่งด่วน

**จับตา:** ติดตามว่าเมื่อ OpenAI ขยายการรวม Chat และ Work ไปยังผู้ใช้ทุกกลุ่ม จะมีการปรับเพดานโควตาหรือแพ็กเกจราคาเพื่อตอบเสียงวิจารณ์หรือไม่

## 2. อัยการสูงสุด 42 รัฐค้าน Character.AI นำแชตส่วนตัวผู้ใช้ออกประมูลในกระบวนการล้มละลาย

กลุ่มอัยการสูงสุดจาก 42 รัฐของสหรัฐฯ ยื่นเข้าแทรกแซงกระบวนการล้มละลายของ Character.ai ซึ่งยื่นขอ Chapter 11 ไปเมื่อเดือนตุลาคม เพื่อหยุดแผนขายข้อมูลผู้ใช้ให้ผู้ประมูลสูงสุด อัยการระบุว่าชุดข้อมูลนี้มีประวัติแชตจากบัญชีในสหรัฐฯ กว่า 21 ล้านบัญชี ในจำนวนนี้กว่า 2.1 ล้านบัญชีเป็นของผู้เยาว์ รวมถึงข้อมูลส่วนบุคคลอย่าง IP address ทั้งที่บริษัทเคยบอกผู้บริโภคว่าจะไม่ขายข้อมูลส่วนตัว ผู้ประมูลที่เปิดเผยแล้วมีเพียงรายเดียวคือบริษัทนิรนามที่เพิ่งจดทะเบียนในเดลาแวร์

กรณีนี้เปิดโจทย์ใหม่ที่วงการ AI ยังไม่เคยตอบชัด คือบทสนทนาที่ผู้ใช้เล่าเรื่องส่วนตัวกับแชตบอตถือเป็น "ทรัพย์สิน" ของบริษัทที่ขายต่อได้หรือไม่เมื่อธุรกิจล้ม ข้อมูลแชตเป็นวัตถุดิบมีค่าสำหรับเทรนโมเดล จึงดึงดูดผู้ซื้อ แต่ความเสี่ยงต่อผู้เยาว์และความเป็นส่วนตัวสูงมาก สำหรับธุรกิจที่ใช้หรือสร้างบริการแชตบอต บทเรียนคือนโยบายความเป็นส่วนตัวต้องครอบคลุมสถานการณ์ขายกิจการหรือล้มละลาย และควรมีกลไกลบข้อมูลที่ผู้ใช้ควบคุมได้จริง

**จับตา:** ผลคำตัดสินของศาลล้มละลายจะกลายเป็นบรรทัดฐานว่าข้อมูลบทสนทนากับ AI ถูกปฏิบัติแบบทรัพย์สินทั่วไปหรือได้รับการคุ้มครองพิเศษ

## 3. Anthropic อัปเกรด MCP ให้ Claude รับ Skills จากแอปภายนอก ทำงานเบื้องหลัง และหยุดถามก่อนทำสิ่งสำคัญ

Techsauce รายงานว่า Anthropic อัปเดตความสามารถใหม่ให้ Model Context Protocol (MCP) มาตรฐานเปิดที่บริษัทเปิดตัวเมื่อราว 2 ปีก่อนเพื่อเชื่อม AI เข้ากับแอปและระบบภายนอก ปัจจุบัน MCP มียอดดาวน์โหลด SDK กว่า 700 ล้านครั้งต่อเดือน มี Connector กว่า 10,000 ตัว และอยู่ภายใต้การดูแลของ Agentic AI Foundation การอัปเดตครั้งนี้ทำให้ Claude รับคู่มือการทำงาน (Skills) จากแอปนั้นๆ ผ่าน MCP ได้ ทำงานใหญ่ทิ้งไว้เบื้องหลังได้ และรู้จักหยุดถามผู้ใช้ก่อนจ่ายเงินหรือลบข้อมูลสำคัญ

เดิม MCP ส่งให้ AI ได้แค่ "เครื่องมือ" อย่างปุ่มสร้างหรือลบ โดยที่ AI ไม่รู้ขั้นตอนที่ถูกต้องของแต่ละแอป จึงทำผิดลำดับหรือทำพังได้ การให้เจ้าของแอปส่งความรู้เชิงขั้นตอนมาพร้อมเครื่องมือจึงย้ายความรับผิดชอบด้านความถูกต้องไปอยู่กับผู้ที่รู้ระบบดีที่สุด สำหรับนักพัฒนาที่ดูแล MCP server นี่คือโอกาสเขียน Skills กำกับวิธีใช้งานของตัวเอง ส่วนผู้ใช้ทั่วไปจะได้ agent ที่ไว้ใจได้มากขึ้นในงานที่มีผลจริง เช่น การชำระเงิน แม้ยังต้องพิสูจน์ในการใช้งานจริงว่าการหยุดถามทำงานสม่ำเสมอแค่ไหน

**จับตา:** ลองดูว่า Connector ที่ใช้อยู่ในองค์กรเริ่มส่ง Skills มาพร้อมเครื่องมือเมื่อใด และนักพัฒนา MCP server ฝั่งไทยจะนำฟีเจอร์นี้ไปใช้หรือไม่

ที่มา: [Techsauce](https://techsauce.co/ai/claude-mcp-update-skills-tasks-elicitation)

## 4. ShellBench ชี้ AI agent ชั้นนำยังพลาดงานชีวิตประจำวันเกินหนึ่งในสาม

งานวิจัยใหม่ภายใต้ชื่อ ShellBench ซึ่งเป็น benchmark สำหรับงานที่คนมอบหมายให้ AI agent ทำจริงในชีวิตประจำวัน พบว่าแม้โมเดลที่ล้ำหน้าที่สุดจาก OpenAI, Anthropic และ Meta ก็ล้มเหลวมากกว่าหนึ่งในสามของครั้ง และเมื่อรวมทุกโมเดลที่ทดสอบ มี 15.7% ของความพยายามที่ละเมิดข้อกำหนดด้านความปลอดภัยอย่างน้อยหนึ่งข้อ จนมักเกิดผลที่ไม่ตั้งใจ ShellBench พัฒนาร่วมกันโดย The OpenClaw Foundation, Parsewave, Hugging Face, Red Hat และ UC Berkeley โดยอิงจากการโต้ตอบของ agent ในโลกจริงแบบไม่ระบุตัวตนกว่า 10 ล้านครั้ง

ผลนี้มาในจังหวะที่ค่ายใหญ่แข่งกันขาย personal agent อย่าง Muse และผู้ใช้หลายล้านคนเริ่มฝากตารางช้อปปิ้งและแผนเดินทางไว้กับ AI จุดแข็งของ benchmark นี้คือดึงจากงานจริงแทนโจทย์สังเคราะห์ แต่ก็ควรระวังว่านิยาม "ความล้มเหลว" และ "ความปลอดภัย" ขึ้นกับเกณฑ์ของผู้สร้าง สำหรับนักพัฒนา ตัวเลขนี้ย้ำว่า agent ที่แตะเงินหรือข้อมูลจริงยังต้องมีขั้นยืนยันจากมนุษย์ ส่วนผู้ใช้ไม่ควรมอบงานสำคัญแบบปล่อยมือทั้งหมด

**จับตา:** ใช้ ShellBench เป็นเกณฑ์อ้างอิงเมื่อเลือก agent มาใช้ในงานจริง และติดตามว่าผู้ผลิตโมเดลจะเริ่มรายงานคะแนนนี้ในการเปิดตัวรุ่นใหม่หรือไม่

## 5. หน่วยงานไซเบอร์อังกฤษเตือน การโจมตีด้วย AI เพิ่มขึ้นชัดเจน เจาะช่องโหว่เก่าด้วยความเร็วใหม่

National Cyber Security Centre (NCSC) ของสหราชอาณาจักรระบุในบล็อกว่าพบการโจมตีไซเบอร์ที่ขับเคลื่อนด้วย AI เพิ่มขึ้นอย่างชัดเจนในช่วงไม่กี่เดือนที่ผ่านมา มีเหตุการณ์หลายครั้งตั้งแต่กันยายนที่ใช้เครื่องมือเจาะระบบอัตโนมัติ ซึ่งเดิมเป็น penetration testing tool ของฝ่ายป้องกัน จนเกิดการบุกรุกและระบบล่ม NCSC ย้ำว่าช่องโหว่ที่ถูกใช้ไม่มีอะไรใหม่ แต่ความเร็วที่ AI เจาะช่องโหว่ง่ายๆ ได้เปลี่ยนไป ช่วงเดียวกับที่เครื่องมือโอเพนซอร์สอย่าง Artex และ Cairn เปิดให้ดาวน์โหลดฟรี และ FBI ก็เคยออกคำเตือนคล้ายกัน

ประเด็นสำคัญคือ AI ไม่ได้สร้างวิธีโจมตีใหม่ แต่ทำให้ "หนี้ทางความปลอดภัย" ที่สะสมมาหลายปี เช่น ระบบไม่แพตช์หรือตั้งค่าหละหลวม ถูกค้นเจอและใช้ประโยชน์ได้ในเวลาอันสั้น ช่องว่างระหว่างการพบช่องโหว่กับการถูกโจมตีจึงหดลงมาก องค์กรที่เคยพึ่งความ "ไม่มีใครสนใจ" จะไม่ปลอดภัยอีกต่อไป ฝั่งนักพัฒนาและทีม IT ควรนำเครื่องมือเจาะระบบอัตโนมัติแบบเดียวกันมาสแกนระบบตัวเองก่อนผู้โจมตีจะทำ และเร่งปิดช่องโหว่พื้นฐานที่ค้างอยู่

**จับตา:** ลองรัน automated pentest กับระบบขององค์กรเพื่อวัดว่าช่องโหว่พื้นฐานที่ค้างอยู่ถูกค้นเจอได้เร็วแค่ไหน
