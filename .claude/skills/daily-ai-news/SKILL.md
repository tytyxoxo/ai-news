# skill: daily-ai-news

## ขั้นตอนที่ 0 — เตรียมการ

1. ตรวจสอบว่า GitHub connector พร้อมใช้งาน — ถ้าไม่มีให้หยุดและแจ้งสาเหตุ
2. กำหนดวันที่ปัจจุบันตาม timezone Asia/Bangkok แล้ว extract ค่าต่อไปนี้:
   - `TODAY` = วันที่เต็ม (YYYY-MM-DD)
   - `YEAR` = ปี (YYYY)
   - `MONTH` = ชื่อเดือนภาษาอังกฤษ (เช่น July)
3. อ่านไฟล์ล่าสุดใน `articles/` ผ่าน GitHub connector เพื่อเก็บ URL ที่เคยรายงานไว้ → `SEEN_URLS` (ดึงจากลิงก์ในบรรทัด `ที่มา: [...](url)` ของแต่ละข่าว)
4. กำหนด `OUTPUT_FILE = articles/{TODAY}-brief.md`
5. ตรวจสอบว่า `OUTPUT_FILE` มีอยู่แล้วหรือไม่ — ถ้ามีและมีเนื้อหาครบให้หยุด แจ้งว่า "ไฟล์วันนี้มีอยู่แล้ว" โดยไม่ต้อง overwrite

## ขั้นตอนที่ 1 — ค้นหาข่าว

อ่านรายชื่อแหล่งข่าวที่อนุญาตและโดเมนจาก `reference/trusted-sources.md` ก่อน — ห้ามใช้แหล่งที่ไม่อยู่ในรายการนั้น

ใช้ WebSearch พร้อมพารามิเตอร์ `allowed_domains` จำกัดเฉพาะโดเมนใน trusted-sources.md (แบ่งเรียกหลายครั้งตาม Tier ถ้าโดเมนเยอะเกินไปสำหรับ query เดียว) ด้วย query ต่อไปนี้ (ห้ามใส่วันที่ตัวเลขแบบ YYYY-MM-DD ลงใน query — WebSearch ไม่รองรับการกรองตามวันที่ การกรอง 24 ชั่วโมงให้ทำที่ขั้นตอนที่ 2 จาก published date จริงของแต่ละข่าวแทน):
- `"AI news today"`
- `"artificial intelligence latest news {MONTH} {YEAR}"` — ใช้เดือนและปีจาก `TODAY`
- `"LLM machine learning news today"`

ผลลัพธ์ที่เป็นหน้า category/tag/archive (เช่น `/tag/ai/page/24`, `/category/artificial-intelligence/`) ไม่ใช่บทความข่าว — ห้ามใช้เป็นแหล่งอ้างอิง ให้มองหาเฉพาะลิงก์ที่ชี้ไปบทความเดี่ยว

## ขั้นตอนที่ 2 — คัดกรองและเลือกข่าว

สำหรับบทความที่ดูมีแนวโน้มเข้าเกณฑ์ ใช้ WebFetch เปิดบทความจริงเพื่อยืนยัน published date ที่แท้จริง — ห้ามเดา published date จาก search snippet เพียงอย่างเดียว เพราะ snippet มักไม่มีวันที่ชัดเจนหรือคลาดเคลื่อน

ถ้าโดเมนอยู่ใน "โดเมนที่ WebFetch เข้าไม่ได้" ใน `reference/trusted-sources.md` ห้ามเสีย call ยิง WebFetch — ใช้วันที่ที่ WebSearch ระบุไว้ชัดเจนแทนได้ (ต้องเป็นวันที่ตัวเลขจริง ไม่ใช่คำกว้างๆ) ถ้าไม่ชัดเจนให้ตัดข่าวทิ้ง

ถ้า WebFetch เข้าถึงบทความได้ตามปกติแต่ล้มเหลว (เช่นโดน paywall หรือ block แบบไม่คาดคิด) ให้ตัดข่าวนั้นทิ้งไปเลย ไม่นับรวมในโควตา 5 ข่าว

กรองด้วย 2 เงื่อนไขนี้เท่านั้น:
1. **24h filter** — เผยแพร่ภายใน 24 ชั่วโมงที่ผ่านมา (Asia/Bangkok) ตามวันที่ที่ยืนยันจาก WebFetch
2. **Dedup filter** — URL ต้องไม่อยู่ใน `SEEN_URLS`

เลือกสูงสุด 5 ข่าวที่ผ่านทั้งสองเงื่อนไข โดย:
- มีแหล่งไทยอย่างน้อย 1 ข่าว ถ้ามี
- มีแหล่งต่างประเทศอย่างน้อย 3 ข่าว
- ห้ามผ่อนเกณฑ์เพื่อให้ครบ 5 — ถ้าได้ 3 ก็ส่งแค่ 3

## ขั้นตอนที่ 3 — วิเคราะห์เชิงลึก

สำหรับแต่ละข่าว ให้คิดวิเคราะห์จาก 3 มุมมองนี้ไว้ก่อน (ใช้ในขั้นเขียนเท่านั้น ไม่ต้องเขียนแยก):
- **มุมวิชาการ** — งานวิจัยหรือแนวคิดอะไรอยู่เบื้องหลัง มีข้อจำกัดหรือสมมติฐานอะไรที่ควรระวัง
- **มุม developer** — กระทบกับเครื่องมือ workflow หรือ stack อย่างไร มีอะไรนำไปใช้ได้จริงทันที
- **มุมผู้ใช้/ธุรกิจ** — เปลี่ยนแปลงการทำงานหรือชีวิตประจำวันอย่างไรในทางปฏิบัติ

## ขั้นตอนที่ 4 — เขียนบทความ

เขียนสไตล์นักวิเคราะห์ที่คนทั่วไปอ่านได้ แต่ลึกพอที่คน tech จะได้ประโยชน์

รูปแบบของแต่ละข่าว:
- **ย่อหน้าที่ 1** (60–80 คำ): ที่มา บริบท และสิ่งที่เกิดขึ้น
- **ย่อหน้าที่ 2** (60–80 คำ): ความสำคัญและผลกระทบ — สอดแทรกมุมมองจากขั้นตอนที่ 3 อย่างเป็นธรรมชาติ ไม่ต้องระบุว่ามาจากมุมไหน
- **จับตา:** (1 ประโยค): สิ่งที่ควรติดตามต่อหรือนำไปลองใช้จริง

ห้ามใช้ bullet point — ทุกส่วนต้องเป็นย่อหน้าต่อเนื่องเท่านั้น

## ขั้นตอนที่ 5 — บันทึกขึ้น GitHub

รูปแบบไฟล์:

```
---
date: {YYYY-MM-DD}
---

## 1. {หัวข้อข่าว}

{ย่อหน้าที่ 1}

{ย่อหน้าที่ 2}

**จับตา:** {ประโยคเดียว}

ที่มา: [{ชื่อเว็บ}]({URL})

---

## 2. {หัวข้อข่าว}

...

---

_สร้างโดย Claude Code Routine เวลา 09:00 น._
```

ใช้ GitHub connector commit ตรงลง branch: main — ห้ามสร้าง branch ใหม่ ห้ามใช้ Bash หรือ git CLI ใดๆ

## กรณีไม่มีข่าวผ่านเกณฑ์

```
---
date: {YYYY-MM-DD}
---

ไม่มีข่าว AI ใหม่ที่ผ่านเกณฑ์ในวันนี้
สาเหตุ: {ระบุ: 24h filter / dedup filter / ทั้งคู่}

_สร้างโดย Claude Code Routine เวลา 09:00 น._
```

## ข้อห้าม

- ห้ามแต่งหรือเดา URL — ใช้เฉพาะที่ได้จาก WebSearch เท่านั้น
- ห้ามใช้แหล่งข่าวนอกเหนือจาก `reference/trusted-sources.md`
- ห้ามใช้ Bash, git CLI หรือ shell ใดๆ
- ใช้ timezone Asia/Bangkok เสมอ
